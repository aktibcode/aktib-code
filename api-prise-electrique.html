Une API, c’est une prise électrique pour logiciels

Derrière chaque paiement en ligne, chaque bulletin météo et chaque réponse de chatbot, il y a une API. Voici ce que c’est, sans jargon.

ALa rédaction 18 novembre 2026 3 min de lecture
Sommaire
  1. Deux logiciels qui ne parlent pas la même langue
  2. La prise, le voltage et le mode d’emploi
  3. Requête, réponse : le dialogue en pratique
  4. Un contrat, pas une télécommande magique
  5. Trois idées reçues à jeter

Vous réservez un train, vous payez par carte, vous consultez la météo sur votre téléphone. Dans les trois cas, un logiciel demande quelque chose à un autre logiciel — et reçoit une réponse en une fraction de seconde. Ce dialogue a un nom : API, pour Application Programming Interface, ou « interface de programmation applicative ».

,

Le mot impressionne. La chose est plus simple qu’elle n’y paraît : une API est un mode d’emploi pour faire parler deux programmes entre eux, sans qu’aucun des deux n’ait besoin de connaître les entrailles de l’autre.

,

Deux logiciels qui ne parlent pas la même langue

,

Imaginez une librairie qui veut afficher les avis de ses clients, mais qui n’a pas d’équipe pour construire un service de modération. Elle utilise une API de modération : elle envoie le texte, reçoit un verdict. Elle n’a pas besoin de savoir quel modèle tourne derrière, ni sur quel serveur, ni dans quel langage il est écrit.

,

Sans API, il faudrait recopier les données à la main, ou connecter directement les deux systèmes. C’est fragile, lent, et chaque changement d’un côté casserait l’autre. L’API ajoute une frontière stable : tant que le contrat ne change pas, chacun peut évoluer de son côté.

,

La prise, le voltage et le mode d’emploi

,

L’analogie de la prise électrique fonctionne étonnamment bien. Une prise standardise trois choses : la forme (les broches entrent ou non), la tension (ce qui circule) et les règles de sécurité (ce qu’on peut brancher sans tout faire disjoncter).

,

Une API fait pareil. Elle définit des adresses (les endpoints), un format d’échange (souvent du JSON, un texte structuré en clés et valeurs) et des règles : quelles données envoyer, ce qui est autorisé, ce qui sera renvoyé en cas d’erreur. Vous branchez votre logiciel, vous respectez le contrat, ça marche.

,
Une API ne vous donne pas la centrale électrique. Elle vous donne une prise aux normes, et le mode d’emploi.
,

Requête, réponse : le dialogue en pratique

,

La plupart des API du web suivent le même rituel. Le logiciel client envoie une requête à une adresse, avec une méthode (lire, créer, modifier, supprimer), éventuellement des paramètres et une clé d’identification. Le service répond avec un code (200 si tout va bien, 404 si la ressource n’existe pas) et des données.

,
httpGET /v1/meteo?ville=Ndjamena
Authorization: Bearer CLE_SECRETE

→ 200 OK
{ "temperature": 34, "ciel": "dégagé" }
,

Ce aller-retour se produit des milliards de fois par jour : quand votre application bancaire vérifie un solde, quand un site affiche une carte, quand un assistant génère une réponse. Vous ne voyez que le résultat. La plomberie, elle, est faite d’API.

,

Un contrat, pas une télécommande magique

,

Une API n’ouvre pas un accès illimité. Elle expose volontairement une partie d’un système, avec des limites : un nombre de requêtes par minute, un périmètre de données, une clé révocable. C’est une porte avec un videur, pas un trou dans le mur.

,

C’est aussi une dépendance. Si le fournisseur change son contrat, augmente ses prix ou ferme le service, votre produit peut s’arrêter du jour au lendemain. Les équipes sérieuses surveillent donc trois choses : la stabilité de l’API, son prix à l’échelle, et ce qui se passe si elle disparaît.

,

Trois idées reçues à jeter

,
  • « Une API, c’est une interface graphique. » Non : pas d’écran, pas de boutons. C’est une interface pour programmes.
  • « Une API publique est gratuite. » Pas forcément. Publique signifie accessible ; gratuite est une décision commerciale, souvent limitée dans le temps ou en volume.
  • « C’est un sujet de développeurs. » Les API décident de ce que votre entreprise peut faire, à quel prix et avec quelles données. C’est aussi un sujet de direction.
,
Le mot du lexique

Retrouvez la définition d’API et de protocole dans notre lexique.

L’essentiel en 3 points

  1. Une API est un contrat qui permet à deux logiciels de se parler sans se connaître.
  2. Elle standardise l’adresse, le format des données et les règles d’accès.
  3. Elle crée de la modularité, mais aussi une dépendance à surveiller.
